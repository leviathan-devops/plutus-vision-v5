## Organ 1 — OBCV as the S/D repair layer

Target seams:

- current canonical P5: `m1/src/p5.ts:1`;
- preserved visual floor: `Checkpoints/v1-ship-approved-working-baseline/dist/plutus-vision-v1.pine:1`;
- donor: `src/mdve/obcv.ts:1`, `src/mdve/bom-mom.ts:1`, and `src/mdve/ob-engine.ts:1` under the v4.5.3 checkpoint.

OBCV becomes a second S/D candidate generator, not a replacement.

```text
current P5 S/D scan ──┐
                      ├── reconciliation ── canonical S/D set
OBCV scan ────────────┘
```

Reconciliation classes:

| Class | Meaning | Action |
|---|---|---|
| `AGREED` | Current P5 and OBCV find the same structural zone | Keep current geometry; attach OBCV metadata |
| `OBCV_MISSING_CURRENT` | Current finds it, OBCV does not | Keep current zone; record disagreement |
| `OBCV_ADDITIONAL` | OBCV finds a valid zone current P5 missed | Add canonical S/D zone with OBCV provenance |
| `EDGE_CONFLICT` | Same origin/timeframe, different edges | Keep current geometry first; record OBCV proposal |
| `REJECT` | Candidate fails displacement/structure/BoM gates | Do not add |

Rules:

1. OBCV does not edit LuxAlgo.
2. OBCV does not replace LuxAlgo.
3. OBCV adds only canonical S/D zones missing from current P5.
4. Every OBCV zone carries displacement, ATR context, structure-break reference, BoM body/wick classification, prior-move classification, parent/child relation, and a deterministic timestamp-derived ID.
5. No wall-clock IDs and no synthetic zones.
6. Canon wins every conflict.

## Organ 2 — LMV as precision metadata

Target seams:

- current LSZ/intra-zone logic: `m1/src/p5.ts:1`;
- card assembly: `m1/src/assemble.ts:1`;
- donors: `src/mdve/lmv.ts:1` and `src/mdve/lqz-matrix.ts:1`.

LMV starts as zone enrichment, not another top-level liquidity family:

```text
canonical zone
   │
   └── assigned LMV rung(s)
         ├── center
         ├── defended edge
         ├── reaction extreme
         ├── sweep count
         ├── touch kinds
         ├── week span
         └── strength ZFP receipt
```

Rendering policy:

| Mode | Default | Purpose |
|---|---:|---|
| `LMV_HIDDEN` | yes | Metadata only; zero object cost |
| `LMV_THIN` | optional | One defended-edge line per selected zone |
| `LMV_INSPECT` | on demand | Table or label with rung details |
| `LMV_ZONE_FAMILY` | forbidden initially | Would duplicate V1 liquidity |

LMV is promoted to a separate visual family only if random-week evidence proves V1 liquidity systematically misses a class.

The immediate LMV contribution to later E2 is the defended edge:

- supply LMV defended edge = floor;
- demand LMV defended edge = ceiling.

## Organ 3 — freshness state machine

Target seam: current reaction metadata in `m1/src/assemble.ts:1`.

Donor: `src/mdve/freshness.ts:1`.

The simple reaction count becomes an event ledger:

```text
zone.reactionEvents = [
  { time, kind, pierce, reclaim, gapThrough, battleResult }

zone.freshness = {
  state: FRESH | TESTED_1X | TESTED_2X | DEPLETED | VIOLATED,
```

The donor supplies event anatomy and state classification. It does not silently replace canonical ZFP. Current 5.3.3 ZFP remains authority.

## Organ 4 — zone-pressure and operative-defense engine

Target seam: `m1/src/assemble.ts:1`.

Donor: `src/mdve/zone-pressure.ts:1`.

Every canonical zone gains:

```text
zone.pressure = {
  lifecycle: VIRGIN | ACTIVE_1 | ACTIVE_2 | DEPLETED | FORTRESS | BROKEN | CONFLUENCE,
  battles: array,
  pierced: boolean,
  nestedLiquidityId: string | null,
  shieldLiquidityId: string | null,
  absorption: boolean,
  operativeDefense: SHIELD_FUEL | PRESSURE_STRUCTURE
}
```

This is the metadata LuxAlgo cannot provide: which liquidity pool shields a zone, when the shield is consumed, when a zone is a fortress, when a break is genuine, and when price gapped over a zone without consuming it.

Default rendering remains tabular/inspect-only to avoid object-budget regressions.
