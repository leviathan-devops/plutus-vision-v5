# PLUTUS VISION — BUILD WORKFLOW v3
## 29 turns. Every turn ends at a gate. The executor decides nothing.

---

# §0 · THE PSTACK MANDATE

Every phase runs on the four pstack substrates. A turn that produces work without them is not a turn.

```
1  verify-plutus/SKILL.md     generated by pstack-create-verification-skill
                              LAUNCH · DOCTOR · DRIVE · EVIDENCE · CLEANUP
                              + features/ (5 files, the 4 fixed H2s)
                              PROVEN by running it once end to end  -> P0.T1
2  THE FEATURE MAP            features/F1..F5 = the coverage denominator
                              a proof that drives one entry point is INCOMPLETE
3  show-me-your-work          PROOF/decision-trail.tsv: one row per decision
                              written by the gate, never by the executor
4  THE PRINCIPLES             encode-lessons-in-structure: the 2nd occurrence of a
                              class becomes a CHECK + a fixture pair
                              attack-the-premise: 2 fixes failing the SAME gate =
                              the premise is wrong, take a census
```

**The enforcement:** a phase whose exit criterion does not name its gate and its card is refused.

# §1 · THE VERIFICATION CARD

The judge never sees the repo. It sees a card. Schema: `vcards/_schema.json`.

```
┌──────────────────────────────────────────────────────────────────────────┐
│ VCARD                                             budget 3,500 tok        │
├──────────────────────────────────────────────────────────────────────────┤
│ IDENTITY   id · phase · gate · feature (F1..F5)                          │
│ CONTEXT    mandate <=2000 · laws <=200 · acceptance <=200                │
│ SUBJECT    path · sha256 · measurements · artifact_sha   (MEASURED)      │
│ CLAIM      the agent's own words this turn, VERBATIM     <=300           │
│ QUERY      noul mandate_met · noul claim_contradicted                    │
│            choice defect_class · score completeness                      │
│ VERDICT    written by the gate, never by the executor                    │
└──────────────────────────────────────────────────────────────────────────┘
```

**Refusal rule:** `tokens(card) > 6,000` -> the gate refuses the card (`CARD_OVERFLOW`). A truncated
card silently destroys the judgement, so it is never sent.

# §2 · THE SIX GATES

| gate | subject | predicate | built? |
|---|---|---|---|
| G0 DOCTOR | the rig | pid alive AND port ours AND build sha == the frozen sha | no |
| G1 ARITHMETIC | the frame | 20 pixel checks C01–C20 | stand-in (`gates/G1.sh`) |
| G2 STRUCTURAL | card + .pine | every receipt re-adds; no stub; no literal price in a draw call | no |
| G3 SEMANTIC | the card digest + the claim | `mandate_met >= act` AND `claim_contradicted < act` | no |
| G4 PERCEPTION | the frame | labels/values read and compared to the card | no |
| G5 AGREEMENT | all verdicts | G1..G4 agree AND the known-bad control is REFUSED | no |

```
EXIT CONTRACT   0 PASS · 1 FAIL · 2 INCONCLUSIVE · 3 VOID/STALE/TAMPERED · 4 GATE_DEFECT
```

**Proven today on G1 and the no-comment-guard predicate — all five paths:**

```
== 1 PASS ==        rc=0
== 2 FAIL ==        rc=1
== 3 VOID stale ==  VOID:STALE_SUBJECT:/tmp/subject-ok.txt   rc=3
== 4 VOID tampered == VOID:GATE_TAMPERED:G1                  rc=3
== 5 GATE_DEFECT == GATE_DEFECT:_dead:negative_rc=0          rc=4
```

The `_dead` gate (a gate that always passes) is REFUSED by the harness. That is the proof the harness
cannot be satisfied by a gate that cannot fail.

# §3 · THE CALIBRATION LAW

```
1  LABEL   20 frame pairs (clean / corrupt) + the golden week's 8 setups
2  SWEEP   act over 0.50 0.60 0.70 0.80 0.90; precision + recall at each
3  READ    max < 0.5      -> THE QUESTION is broken, rewrite it
           spread < 0.25  -> the question does not discriminate
4  CONTROL positive >= 0.85 AND negative <= 0.15 on EVERY arm
5  RECORD  act · the sweep · the date · the model id  -> calibration/g3.json, g4.json
```

A gate whose `act` is not in a calibration file is `E_UNCALIBRATED` and refuses to judge.

# §4 · THE SELF-VALIDATING LOOP

```
OUTER (per turn)
  a  the executor does the turn's work
  b  the turn ends at its gate
  c  PASS -> the gate writes the verdict + the TSV row; the next turn opens
     FAIL -> the card's defect_class routes the fix (S5)
     INCONCLUSIVE -> supply the missing input; an absence is never a pass
     VOID -> the gate failed its control: repair the GATE, then redo
  d  a phase closes ONLY on a PASS whose exit criterion names the card

INNER (the gate validating itself, every run)
  1  the gate runs its own good/bad fixtures FIRST
  2  they do not separate -> exit 4 GATE_DEFECT, judge nothing
  3  recompute the subject sha vs the card's; mismatch -> exit 3
  4  the gate writes the verdict; the executor writes NOTHING
```

**Four mechanical things make waking up to a correct build possible:** the hook (no PASS row, no
commit), the ledger (TSV + one verdict per judged unit), the control (every run proves the judge can
see), the record (`runtime/record.json`).

# §5 · THE FAILURE-CLASS ROUTING

```
defect_class          owner layer            the fix goes there
──────────────────────────────────────────────────────────────────────────
MISREAD_VALUE         L0 capture/extract     the field schema or an invariant
TIER_PROMOTION        E1 tier predicate      the conjunction, not the threshold
RECEIPT_BROKEN        E1 zfp.compute         the arithmetic or the modifier gate
UNLICENSED_SHAPE      E2 candidate filter    the LICENSED table
CHAIN_ORDER           E2 walk                the transition table
GEOMETRY_WRONG        E3 geometry            entry/SL/TP from the zone edges
CLAIM_FALSE           the executor           the claim, not the gate
RENDER_WRONG          L3 kernel              the draw order or the cast
```

**Second occurrence of a class** -> it becomes a CHECK plus a fixture pair (encode-lessons-in-structure).
**Two fixes failing the SAME gate** -> the premise is wrong; census, re-derive (attack-the-premise).

## P0 · INSTRUMENT — 7 turns, runnable now

```
P0.T1  THE DRIVER
  A  run pstack-create-verification-skill against PLUTUS_VISION ->
     verify-plutus/SKILL.md (LAUNCH/DOCTOR/DRIVE/EVIDENCE/CLEANUP) + features/F1..F5
  E  the generated skill; the 5 feature files; a DRIVE run against F1
  R  the driver is generated, not hand-written; the feature map is the denominator
  G  the generated skill RUNS once: LAUNCH -> DOCTOR -> DRIVE F1 -> EVIDENCE -> CLEANUP
     rc=0 AND the evidence file survives cleanup
  C  feat(p0): verify-plutus generated and proven once

P0.T2  G0 DOCTOR
  A  write gates/G0.sh; fixtures/G0.good|bad; pin
  E  gate.sh G0 fixtures/G0.good -> 0 ; fixtures/G0.bad (dead pid) -> 1
  R  the rig is worth driving only if the pid, the port and the build sha all agree
  G  G0 rc=0 on the live rig AND rc=1 on the dead-pid fixture
  C  feat(gates): G0 doctor with a dead-pid negative

P0.T3  G2 STRUCTURAL
  A  write gates/G2.sh: every zone node's receipt re-adds; no stub; no literal price
  E  gate.sh G2 card-good -> 0 ; card-broken (base+mods != raw) -> 1
  R  pixels cannot show a receipt that does not add up
  G  G2 rc=0/rc=1 on the pair AND firewall.sh rc=0
  C  feat(gates): G2 structural

P0.T4  G4 PERCEPTION
  A  write gates/G4.sh: Clairic reads zfp_labels/tier_labels/zone_count; code compares
  E  good frame -> 0 ; slab -> 1 ; the slab's band count printed
  R  the model reads; the code decides
  G  G4 rc=0 on the good frame AND rc=1 on the slab
  C  feat(gates): G4 perception with the known-bad control

P0.T5  G3 SEMANTIC + CALIBRATION
  A  write gates/G3.sh; label 20 pairs; sweep act; write calibration/g3.json
  E  the sweep table; the chosen act; the positive/negative controls
  R  a threshold without a sweep is a copied number
  G  positive >= 0.85, negative <= 0.15, and act exists in calibration/g3.json
  C  feat(gates): G3 semantic with a derived act

P0.T6  G5 AGREEMENT
  A  write gates/G5.sh: G1..G4 agree AND the control is refused
  E  disagreement -> 2 ; control passes -> 3
  R  agreement is the only thing that turns four opinions into a verdict
  G  G5 rc=0 on the golden frame AND rc=2 on a forced disagreement AND rc=3 on a passing control
  C  feat(gates): G5 agreement + control void

P0.T7  THE HOOK + THE RECORD
  A  write .githooks/pre-commit: refuse a commit touching a judged artifact without a PASS row
  E  a commit attempt without a row -> refused; with a row -> accepted
  R  the hook is what makes the gate unskippable
  G  the hook refuses the unproven commit (rc!=0) AND accepts the proven one (rc=0)
  C  chore(gates): pre-commit hook + runtime/record.json
```

# §10 · THE DEBUG LOOP (bounded)

```
FAIL -> read the card's defect_class -> fix the OWNER layer -> re-run the SAME gate on the SAME subject
three rounds maximum on one gate. On the third: the premise is wrong. Census, re-derive.
a fix that makes a different check fail is a NET REGRESSION: restore and narrow.
```

# §12 · THE SELF-CHECK (this can fail)

```
[ ] can any turn close on a file property, a count, or a sha?              NO  (§8 G lines are gates)
[ ] can the executor edit the gate or write the verdict?                   NO  (gate.sh writes it)
[ ] is there a card for every judged unit, and does it fit its budget?     YES (_schema.json + refusal)
[ ] does every arm carry a positive AND a negative control?                YES (control_pair, exit 4)
[ ] is every threshold backed by a recorded sweep?                         YES (§3; E_UNCALIBRATED)
[ ] does the record allow a cold agent to resume at the exact next turn?   YES (§9)
[ ] does the feature map define coverage, or is it "what I remembered"?     MAP (features/F1..F5)
[ ] if every agent lied, what would still be caught?                       G2 receipts + G4 labels + G5 control
[ ] if the judge were blind, what would catch it?                          the control -> VOID (exit 3)
```

**The residual:** G0, G2, G3, G4, G5 are specified and fixture-paired but NOT yet written. P0.T2–T6
are the turns that build them, and until they exist the ladder above P0 is a design, not a capability.
