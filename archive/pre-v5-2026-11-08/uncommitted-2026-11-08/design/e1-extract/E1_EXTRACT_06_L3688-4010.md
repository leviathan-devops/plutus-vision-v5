### 10.1 Core Design Principles [L3706-L3716]

> `**PRINCIPLE 1: One Indicator, Four Pairs.** A single Pine Script file handles all 4 pairs. The indicator detects which chart it's applied to via `syminfo.ticker` and renders ONLY that pair's data. This eliminates the need for 4 separate scripts.` [L3708]

> `**PRINCIPLE 2: Each Pair Maps ONLY to Its Own Chart.** DXY zones never appear on the EUR/USD chart. EUR/USD zones never appear on the DXY chart. There is zero cross-mapping. The pair detection logic ensures complete isolation.` [L3710]

> `**PRINCIPLE 3: No Mathematical Conversion in Code.** The Pine Script code contains ONLY the final, verified zone data for each pair. It does NOT contain any DXY formula, any conversion logic, or any arithmetic relationship between pairs. Each pair's data arrays are populated with pair-specific levels that were verified through Layer 2.` [L3712]

> `**PRINCIPLE 4: S/D Zones Are NOT Mapped.** 4H BoM/MoM Supply/Demand zones are excluded from the Pine Script indicator entirely. The user maps these manually. Only IP zones, LSZ zones, and option strike targets are auto-rendered.` [L3714]

> `**PRINCIPLE 5: All Drawings Use `xloc=xloc.bar_time`.** Every box, label, and line uses timestamp-based coordinates. Bar index coordinates are PROHIBITED because they cause "bar index too far back" errors on charts with limited history.` [L3716]

### 10.2 Code Structure Template [L3718-L3739]

> `The generated Pine Script code follows this exact structure:` [L3720]

Template block (reproduced whole):

```
1. Header comment block with version, pair list, chart contents
2. indicator() declaration with max_boxes/labels/lines counts
3. Input toggles (IP Zones, LSZ, Option Strikes, Info Table)
4. Zone date range timestamps (2 weeks back + 3 weeks forward)
5. Color definitions (Pressure Ladder: RED/ORANGE/TEAL × 6 tiers)
6. Color helper functions (zfill, zbord, pressureLbl)
7. LSZ color definitions
8. Pair detection logic (syminfo.ticker matching)
9. Data arrays — DXY (IP zones, LSZ, options, trades, macro shape)
10. Data arrays — EUR/USD (same structure)
11. Data arrays — GBP/USD (same structure)
12. Data arrays — AUD/USD (same structure)
13. Helper functions (volLbl, calcZFP with pair-specific reference)
14. Drawing blocks — one per pair (DXY, EU, GU, AU)
    Each block: IP Zones → LSZ → Options → Table
15. No fallback for unknown tickers (clean fail — nothing renders)
```

### 10.3 Pair Detection Logic [L3741-L3753]

Template code block (reproduced whole):

```pine
string ticker = str.upper(str.replace(syminfo.ticker, "/", ""))
bool isDXY = ticker == "DXY" or ticker == "DX-Y.NYB" or str.contains(ticker, "DXY")
bool isEU  = ticker == "EURUSD" or ticker == "EURUSD=X" or str.contains(ticker, "EURUSD")
bool isGU  = ticker == "GBPUSD" or ticker == "GBPUSD=X" or str.contains(ticker, "GBPUSD")
bool isAU  = ticker == "AUDUSD" or ticker == "AUDUSD=X" or str.contains(ticker, "AUDUSD")
bool isKnown = isDXY or isEU or isGU or isAU
string pairLabel = isDXY ? "DXY" : isEU ? "EUR/USD" : isGU ? "GBP/USD" : isAU ? "AUD/USD" : "UNKNOWN"
```

[L3743-L3751]

> `**Rationale:** TradingView uses different ticker formats depending on the data source. The detection must handle: pure ticker ("EURUSD"), Yahoo-style suffix ("EURUSD=X"), and partial matching (str.contains) as fallback.` [L3753]

### 10.4 Zone Date Range Specification [L3755-L3769]

Template code block (reproduced whole):

```pine
int tsL   = timestamp(YYYY, M, D, 0, 0, 0)      // 2 weeks before data week start
int tsR   = timestamp(YYYY, M, D, 23, 59, 59)    // 3 weeks after data week end
int tsMid = (tsL + tsR) / 2                        // Midpoint for labels
```

[L3757-L3761]

Calculation procedure (numbered content kept as sourced bullets):

> `**Calculation from data week:**` [L3763]

> `- Data week = Monday through Friday (e.g., Apr 20-24, 2026)` [L3764]

> `- `tsL` = data week Monday minus 14 days = Apr 6, 2026` [L3765]

> `- `tsR` = data week Friday plus 21 days = May 15, 2026` [L3766]

> `- Total span = ~6 weeks` [L3767]

> `**This range is HARDCODED in the script.** When the user provides new data, the timestamps must be updated to match the new data week.` [L3769]

### 10.8 ZFP Calculation — Pair-Specific Reference Ranges [L3860-L3876]

Template code block (reproduced whole):

```pine
calcZFP(float tp, float bt, string pair) =>
    float zoneW = tp - bt
    float refRange = pair == "DXY" ? 1.60 : pair == "EUR/USD" ? 0.0200 : pair == "GBP/USD" ? 0.0200 : 0.0150
    int pct = math.round(zoneW / refRange * 100.0)
    pct
```

### 10.11 Pine Script Generation Rules (ZERO-TOLERANCE) [L3896-L3921]

> `**RULE PG1: ALL pair data must come from verified Layer 2 sources.** No pair zone in the Pine Script may use a price level that was not verified through the Layer 2 Verification Protocol. If a zone failed Layer 2, it is EXCLUDED from the code.` [L3898]

> `**RULE PG2: NO mathematical conversion code.** The Pine Script code must NOT contain:` [L3900]

> `- The DXY formula` [L3901]

> `- Any reverse conversion function` [L3902]

> `- Any arithmetic relationship between pair price levels` [L3903]

> `- Any `K` factor computation` [L3904]

> `- Any reference to "conversion" or "equivalence" in variable names` [L3905]

> `**RULE PG3: Timestamps must be correct for the data week.** The `tsL` and `tsR` values must be calculated from the actual data week dates, not hardcoded from a template.` [L3907]

> `**RULE PG4: Zone ordering must be top-to-bottom.** IP zones must be sorted from highest price to lowest price (RESISTANCE at top, SUPPORT at bottom). This matches the visual chart layout.` [L3909]

> `**RULE PG5: Table row indexing must be exact.** The table is 2 columns × 17 rows. Row indices 0-16 are allocated as specified in Section 10.7. Any deviation causes "table row out of bounds" error.` [L3911]

> `**RULE PG6: Drawing limits must be set high enough.** `max_boxes_count=2000, max_labels_count=2000, max_lines_count=2000` to accommodate all 4 pairs' drawings.` [L3913]

> `**RULE PG7: `var` keyword for data arrays.** All data arrays must use `var` declaration so they are initialized only once on the first bar.` [L3915]

> `**RULE PG8: No abbreviations in pressure labels.** "MODERATE-HEAVY" is spelled out fully, not "MOD-HEAVY" or "MOD-HEAVY". "Extreme" not "EXT", "Heavy" not "HVY".` [L3917]

> `**RULE PG9: S/D zones are NOT in the code.** 4H BoM/MoM zones are never included in the Pine Script. Only IP zones, LSZ, and option strikes.` [L3919]

> `**RULE PG10: Each pair's drawing block is independent.** The `if barstate.islast and is[Pair]` block for each pair contains its own complete drawing logic. No shared state between pair blocks except color definitions and helper functions.` [L3921]

### 10.13 Pair Translation Audit — Pine Script Verification [L3948-L3961]

> `After generating the Pine Script code, perform these verification checks:` [L3950]

Procedure (numbered steps kept verbatim):

> `1. **Price Level Sanity:** For each pair, verify that ALL zone prices are within 3% of the pair's verified spot price from Layer 2` [L3952]

> `2. **Direction Consistency:** DXY RESISTANCE zones map to pair SUPPORT zones (inverted), DXY SUPPORT zones map to pair RESISTANCE zones (inverted)` [L3953]

> `3. **No Formula Remnants:** Search the code for any occurrence of "1.7361", "0.576", "50.14348112", "K /", or any mathematical conversion expression` [L3954]

> `4. **Zone Ordering:** IP zones are sorted highest-to-lowest within each pair` [L3955]

> `5. **LSZ Consistency:** LSZ zone widths are similar to IP zone widths for the same pair` [L3956]

> `6. **Option Strike Proximity:** Each option strike price is near (within 0.5% of) an IP zone on that pair's chart` [L3957]

> `7. **Table Completeness:** All 17 rows are populated for each pair` [L3958]

> `8. **Timestamp Validity:** `tsL` is 14 days before data week start, `tsR` is 21 days after data week end` [L3959]

> `**Output:** `"Pine Script Verification: [X]/8 checks passed | [list any failures]"`` [L3961]

### E.4 Known Pine Script v6 Constraints [L3994-L4004]

Table (reproduced whole):

| Constraint | Impact | Mitigation |
|:---|:---|:---|
| `var` arrays initialized once | Can't dynamically resize | Pre-size arrays via `array.from()` |
| `xloc.bar_time` required | Timestamps must be valid | Calculate from data week dates |
| No ternary chains for arrays | Can't use `isDXY ? dxy_zTp : eu_zTp` | Separate `if/else` blocks per pair |
| `color.new()` for opacity | `color.rgb()` alpha doesn't render | Always use `color.new(base, 70)` |
| `label.style_none` for floating text | Other styles have background boxes | Use `style_none` for all zone labels |
| `max_boxes_count` limit | Default 500 may be too low | Set to 2000 in indicator() declaration |
| Table cell text no wrapping | Long text may be clipped | Keep text concise in table cells |
